# 名目CFR動画の解析と時刻補正（Issue #18）

## 実測した原因

実機a6/a7で元動画のJSON解析は成功している。`r_frame_rate=30000/1001` と
`avg_frame_rate=1861699207/62118759` の厳密一致判定が入力を拒否していた。
相対差は約1.00012×10⁻⁶。先頭60秒のパケット時刻には揺れと短い間隔・長い間隔が
あるため、平均FPSの差だけを緩めて従来のrawvideo出力を続けると時刻を失う。
元ファイル名・パス・映像は公開しない。

## 修正する契約

- 有効な名目FPSと平均FPSの相対差が1/100000（0.001%）以下なら名目CFRとして受理する。
  今回の実測差を含む限定的な許容幅であり、任意のVFRを受け入れる仕様ではない。
  不明・ゼロ・負・240超のFPS、大きな不一致、HDR、対象外音声などは従来どおり拒否する。
- 出力FPSは平均値に丸めず、名目FPSの正確な有理数を保つ。
- 受理した動画は読み込み時にFFmpegの`fps`フィルターで時刻に基づく間引き・複製を行い、
  同じ固定FPSのrawvideoとしてNPUへ渡す。開始時刻0で映像の開始遅れも反映する。
  元の可変時刻の保存は保証しない。音声は元動画からコピーし、再エンコードしない。
- 60秒プレビュー、短い動画、キャンセルと原本・既存出力保護を維持する。
- 判定境界と不正FPS、実FFmpegの時刻補正・音声・短尺/60秒の回帰テストを先に追加する。
  Windows CIと実機NPUを別に報告する。1080pの60秒実NPU完走は別途検証が必要。

FFmpegの動作根拠: [公式fpsフィルター仕様](https://ffmpeg.org/ffmpeg-filters.html#fps-1)。
