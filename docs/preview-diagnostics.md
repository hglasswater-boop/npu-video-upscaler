# Issue #15: 0%プレビュー失敗の診断

2026-10-11。v0.2.0a5の実機失敗にはトレースバックがなく、原因は未確定。
既存ブランチはa5と同じコードで、mainにある引き継ぎ資料を取り込んだ。

## 仕様

- 入力検査、FFmpeg準備、動画情報解析、NPUモデル読み込み、変換準備、
  デコード、NPU推論、エンコード、出力確定、後処理を区別する。
- 失敗時は例外連鎖と全スタックのファイル名・行番号・関数名、バージョン、
  プレビュー設定、発生段階をLocalAppData/NpuVideoUpscaler/Logsへ保存する。
  ローカル変数、映像、音声、ffprobeのJSON全文は保存しない。
  入力・モデル・出力・ユーザーディレクトリなどのパスはマスクする。
- GUIは短い日本語の段階表示と失敗通知・ログ保存先を提供する。
  ログ保存不能でも元の例外を置き換えず、保存できなかったことを知らせる。
  キャンセルは失敗ログにしない。
- ffprobeは有限のタイムアウトを設定し、None/空/不正JSON/null/配列などを
  日本語MediaErrorとして拒否。終了コード・stderrと例外原因を保持する。
- Windowsのロケール依存デコードを調査する。UTF-8メタデータを含む実際の
  子プロセス出力で再現を確認し、ffprobeのJSONを明示的UTF-8で読む。
  異常応答を空オブジェクトとして受理することは禁止。
- NPU専用、60秒上限、音声コピー、原子的出力、同意付きセットアップ・更新は維持。
- 引き継ぎ仕様の「60秒プレビューを初期選択」をGUIで明示する。
  a5のレイアウトはチェック未選択だったため、初期値を1行で修正する。

## 検証の境界

回帰テストではffprobe異常、NPU内部例外、パス秘匿、保存失敗、キャンセルと
GUI通知を確認する。Windows CIは実FFmpegの音声・60秒・キャンセル、凍結exeと
インストーラを確認する。モデル推論のmockは実機NPUの証拠ではない。
125Hで新版のログを取得するまで、元の実機障害の解消を宣言しない。

## 2026-10-11の実データ再現

利用者指定のネットワーク共有上の動画で旧処理を実行した。
Windows / Core Ultra 5 125H / Python 3.11.9 / locale CP932 において、
subprocessの_readerthreadがUTF-8出力をCP932で読みUnicodeDecodeErrorとなる。
stdout=Noneとなり、json.loadsが報告と同一のTypeErrorを発生させた。
診断ログを保存し、修正後は同じファイルのJSON解析を通過した。
ただし既存のr_frame_rateとavg_frame_rate一致条件を満たさずMediaErrorとなる。
元動画のフルパスやタイトルは資料・公開ログに記載しない。

この検証はJSON例外の原因と修正を実証するが、当該動画の変換成功を意味しない。
CFR/SDR入力を使ったNPU変換は別途Issue #3で検証する。
