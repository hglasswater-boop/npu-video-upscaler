# 常時表示する変換進捗

## 問題

a8は1フレームが終わるまで進捗が更新されず、整数%では1/1798も0%になる。
フレーム数は次の段階表示で上書きされる。実機1080pの最初のフレームには約54秒かかり、
処理が進んでいることが分からない。

## 契約

- 処理段階とは別の常時表示欄に、全体の割合（小数3桁）、完了/推定全フレーム数、
  現在のフレーム内の完了/全タイル数、経過時間と残り時間の目安を表示する。
- タイル推論と出力領域へのコピーが完了した時点だけを実進捗として数える。
  準備やNPUモデルコンパイル中は段階を示し、進捗や残りを捏造しない。
- Qtへのタイル通知は最大毎秒4回程度に抑える。フレームの開始/最後は通知する。
- 残り時間は少なくとも1フレーム完了後に処理速度から計算し、「目安」と明記する。
  総フレーム数不明時や準備中は「計算中」。秒数は時間・分・秒で表示する。
- 出力の確定が成功するまで100%にしない。失敗・キャンセル時も到達した進捗は保持する。
- NPU専用推論、タイル内容、キャンセル、音声と原本保護は変更しない。
- 回帰テスト→最小修正→Windows CI→PR→新しいa9の公開で進める。
  現在進行中の利用者の変換を更新のために中断しない。更新は完了後に適用する。
