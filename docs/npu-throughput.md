# NPUの処理速度改善 — Issue #3

## 現状と調査

a9の実機125Hで1080pの先頭60秒は約1798フレーム。48×48入力モデルから
周囲8pxを除いた32×32の領域を採用するため、1フレーム2040回の推論が必要。
現在は各タイルを同期推論してから次へ進む。約28時間というGUIの残り表示は
短時間の速度からの目安であり、完走を計測した値ではない。

まず実機で同期呼び出し、推論要求の再利用、少数の非同期要求、THROUGHPUT指定を
同じ入力・同じモデルで比較する。競合する変換を停止できる場合のみ速度を比較し、
コンパイル/初回推論とウォーム時の速度を区別する。NPU実行先を記録し、前処理・
推論・後処理・映像読み書きの時間を分離する。

## 改善の受け入れ条件

- モデル推論は常にNPU。CPU/GPU/AUTO/MULTI/HETEROへ自動切替しない。
- 同じ重み・入力・タイル位置・周囲8px・出力領域を維持する改善を先に評価する。
- 非同期処理の同時要求数とメモリ使用を制限し、出力領域と要求を正しく対応させる。
  順不同の完了、入力/出力バッファ再利用、途中エラー、キャンセルを回帰テストする。
- 進捗は実際の出力領域コピー完了を数える。キャンセル後は未完了要求を安全に待ち、
  既存の完成出力と原本を保持する。60秒・音声・FPS・出力確定は維持する。
- 候補を実機で比較し、数値と画素の一致/差分を確認してから本番採用する。
  タイルサイズやモデルそのものの変更が必要なら、別途画質・境界・互換性を評価する。
- 仕様→失敗テスト→最小修正→ローカル/Windows CI→PR→新しい不変alpha→実機更新。
  実行中の変換を中断する操作は、その変換を止める利用者の承認後に行う。

## 根拠

OpenVINOの[NPU Plugin](https://github.com/openvinotoolkit/openvino/blob/master/src/plugins/intel_npu/README.md)
は複数非同期要求と推奨要求数、NPU割当済みテンソルの利用を説明している。
推奨要求数はモデル別の速度保証ではないため、125Hで実測して判断する。

## 同時要求の実装契約

`NpuTilePool`はモデルの推奨要求数を上限4へ制限した要求プールを保持する。
`infer_tiles`は入力と出力領域の組を受け取り、要求専用入力バッファへコピーして
非同期で投入する。借用する出力バッファは呼び出し側の画素コピーが終わるまで
再利用しない。キャンセル/失敗時も投入済み要求を全て待ってから終了する。
`upscale_frame`の純粋な同期タイル関数によるテスト経路と同じ切り出し・コピーを
共有し、実アプリはNPU要求プールを使う。実機計測で改善がない候補は採用しない。
