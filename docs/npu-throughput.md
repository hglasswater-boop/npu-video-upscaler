# NPUの処理速度改善 — Issue #3

## 現状と調査

a9の実機125Hで1080pの先頭60秒は約1798フレーム。48×48入力モデルから
周囲8pxを除いた32×32の領域を採用するため、1フレーム2040回の推論が必要。
現在は各タイルを同期推論してから次へ進む。約28時間というGUIの残り表示は
短時間の速度からの目安であり、完走を計測した値ではない。

まず実機で同期呼び出し、推論要求の再利用、少数の非同期要求、THROUGHPUT指定を
同じ入力・同じモデルで比較する。競合する変換を停止できる場合のみ速度を比較し、
コンパイル/初回推論とウォーム時の速度を区別する。NPU実行先を記録し、前処理・
推論・後処理・映像読み書きの時間を分離する。

## 改善の受け入れ条件

- モデル推論は常にNPU。CPU/GPU/AUTO/MULTI/HETEROへ自動切替しない。
- 同じ重み・入力・タイル位置・周囲8px・出力領域を維持する改善を先に評価する。
- 非同期処理の同時要求数とメモリ使用を制限し、出力領域と要求を正しく対応させる。
  順不同の完了、入力/出力バッファ再利用、途中エラー、キャンセルを回帰テストする。
- 進捗は実際の出力領域コピー完了を数える。キャンセル後は未完了要求を安全に待ち、
  既存の完成出力と原本を保持する。60秒・音声・FPS・出力確定は維持する。
- 候補を実機で比較し、数値と画素の一致/差分を確認してから本番採用する。
  タイルサイズやモデルそのものの変更が必要なら、別途画質・境界・互換性を評価する。
- 仕様→失敗テスト→最小修正→ローカル/Windows CI→PR→新しい不変alpha→実機更新。
  実行中の変換を中断する操作は、その変換を止める利用者の承認後に行う。

## 根拠

OpenVINOの[NPU Plugin](https://github.com/openvinotoolkit/openvino/blob/master/src/plugins/intel_npu/README.md)
は複数非同期要求と推奨要求数、NPU割当済みテンソルの利用を説明している。
推奨要求数はモデル別の速度保証ではないため、125Hで実測して判断する。

## 実測で棄却した候補

実機125H/OpenVINO 2026.4.1/ドライバー32.0.100.4724、48pxの同じ乱数入力64タイル、
3回の中央値。LATENCY同期1.683秒に対し、非同期2件1.796秒、4件1.821秒、8件1.839秒。
THROUGHPUT同期1.636秒、非同期4件1.881秒。再利用した内部テンソルでの同期推論も
速くならなかった。各候補の浮動小数出力は一致したが、速度改善がないため、
追加した非同期プールとその専用テストを取り除く。本番は同期経路を維持する。

96pxのNPUコンパイルは成功し、16タイルの同期中央値1.628秒。
1080pで必要なタイル数は2040→336。単純換算は約53.6→34.2秒/フレームだが、
実際の1080pフレームの入出力・画質評価前の推定である。128pxも比較して判断する。
利用者の指示により、軽量モデルへは切り替えずBSRGANの重みを維持する。

## 採用候補：既存BSRGANの128pxタイル

128pxでは16タイル中央値2.419秒、1080pは180タイルで推論時間換算約27.2秒。
192pxは16タイル5.893秒、77タイルで約28.4秒で、128pxより改善しなかった。
NPUで成功する128pxを候補とし、元動画の同一フレームで48/128/48/128を実測する。

- 正規の検証済みBSRGANキャッシュだけ、読み込んだIRをメモリ上で128×128へ
  reshapeし、静的NPUコンパイルする。元XML/BIN・重み・演算精度は変えない。
- 小さい画像のパディング増加を避け、動画の縦横が両方256px以上の場合だけ
  大きいタイルを使う。小さい動画は従来形状を維持する。
- 外部手動モデルとモデルZIPの初回互換性検査は従来の静的形状で行う。
- 詳細設定の「大きいタイルで処理を効率化（BSRGAN）」を初期選択し、設定を保存。
  解除すると従来48pxに戻る。推論結果は周囲の入力範囲が変わるため完全一致とは
  限らない。境界・色・細部を比較し、この違いと実測速度を記録する。
- 128pxのコンパイル失敗は診断付きエラーとし、自動的に別デバイスへ切り替えない。
- コンパイルの再実行を抑えるため、拡大タイルだけユーザー別NPUキャッシュを使う。
  本体の更新時にモデルZIPを再配布・再ダウンロードする必要はない。

同一1080pフレームの48/128/48/128比較では、全処理57.36/36.42/64.21/35.37秒。
中央値60.79→35.90秒（約1.69倍）。出力間MAE 0.581/255、PSNR 46.89dB。
これは従来出力との違いを示す値であり、主観的画質の同等性を証明しない。
追加でNPUコンパイラのoptimization-level=2 / performance-hint-override=latencyを
実測する。重み・精度・画素差を確認し、改善した設定だけ採用する。
長時間処理には公式が推奨しないNPU_TURBOは今回有効化しない。
